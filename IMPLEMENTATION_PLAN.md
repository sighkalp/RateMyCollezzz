# Component Workflow

Every substantial component follows this process:

1. Define exactly what is being built.
2. Explain every important concept.
3. Identify architecture ownership.
4. Identify permitted files.
5. Identify forbidden files.
6. Study relevant existing / legacy code when useful.
7. Create implementation contract.
8. Implement only approved scope.
9. Run tests.
10. Inspect changed files.
11. Explain the implementation deeply.
12. Verify user understanding.
13. Lock the component.
14. Move to the next component.

---

# Completion Principle

A component is NOT complete merely because code runs.

Completion requires:

- architecture respected
- correct files modified
- no unapproved files
- no duplicate logic
- no unnecessary abstraction
- expected behaviour verified
- tests passing where applicable
- FILE_MAP.md updated
- implementation understood
- no unresolved scope deviation

Only then can a component be marked LOCKED.
